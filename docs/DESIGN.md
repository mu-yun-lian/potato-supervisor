# 土豆监督员：安卓离线开源项目设计方案

版本：设计稿 v1.2（试用反馈增补版）  
日期：2026-10-06（v1.1 基线形成于 10 月 5 日，Asia/Shanghai）  
用途：交给工作模式作为实现依据。本文是需求与技术设计，不是已经完成开发或通过实机验证的报告。
修订依据：用户明确要求以帮助学生回到学习任务为主线，打开选定应用即出现角色劝阻；接受按钮理由后暂时放行，五分钟使用后追问，多次后强制退出。v1.1 补齐执行规则，保留原稿中的安卓、离线、低成本和 GitHub 开源方向。

## 1. 项目定位与已经确定的约束

做一个帮助学生在分心时回到具体学习任务的独立安卓应用。学生预先选择容易让自己分心的应用并主动开启学习时段；每次确认进入这些应用时，土豆角色立即出现，引用当前任务进行劝阻。学生选择“我来搜资料”或“休息一下”，土豆先接受这个理由，暂时放行；累计使用五分钟后再次出现，记住上次的理由继续追问。默认允许三次放行，最后一段用完后自动尝试返回桌面，冷却期内再次进入仍拦截。

这里的“娱乐应用”是学生自己选择的监督对象，下文统称“目标应用”；不由软件推断应用内容。视频应用可能用于搜学习资料，因此不把进入目标应用直接判定为偷懒。两种理由影响台词，不免除约定的监督规则。

“强制退出”的工程含义是：在用户预先同意的限制模式下，返回桌面并阻挡冷却期间的再次使用；不结束第三方进程，不停止其后台音频，不清除其后台任务。界面不使用“已杀掉应用”等不实文案。

学习干预主线是“打断冲动 → 想起本次任务 → 给短暂缓冲 → 追问 → 达到约定后退出”。提醒应给出可执行的小动作，如“回到你写下的任务，先完成第一题”，而不只重复辱骂。是否帮助学习是待验证目标，不宣称已经提升成绩。

目标是低成本个人开源项目，提供好玩、可安装、可验证的真实功能，便于社区贡献语料和角色。Star 是传播目标，不是可保证的验收指标。

确定约束：

- 安卓优先；iOS 是独立后续阶段，不要求首版跨平台。
- 核心功能完全本地运行；不用大模型、账号、云数据库、服务器、广告或付费接口。
- 毒舌与娱乐性是核心风格，提供温和、吐槽、毒舌三档；不能把用户未选择的温和风格强行变成唯一方向。
- 默认角色意图是《植物大战僵尸》的土豆地雷。素材授权与代码许可分别处理，不能把官方素材默认归入开源代码许可。
- 核心交互使用按钮；自由输入仅用于目标、任务、寄语和自定义台词，不解析自由聊天。
- 不分析用户看了什么视频，不判断真假学习，不读取聊天、密码、视频文字或屏幕截图。
- 限制只作用于用户选定娱乐应用，允许停止监督、撤销权限、卸载和紧急解除。
- 首版不做关机、杀第三方进程、设备管理员、Root、设备所有者、反卸载和整机封锁。

## 2. 仍然存在的问题，以及本方案的处理

| 问题 | 判断 | 本方案处理 |
|---|---|---|
| 是否必须用 AI | 不必，连续对话可以由本地状态与模板实现 | 规则引擎 + JSON 语料 + 占位符 |
| 是否能准确知道用户在刷娱乐内容 | 应用在前台不等于内容是娱乐 | 文案只引用使用、按钮选择和次数，不声称识别到撒谎 |
| 是否可以绝对强制 | 普通自律应用不能保证不可绕过 | 定位为约定后的应用拦截，明确权限和后台限制 |
| 安卓上能否稳定运行 | 存在设备、系统、权限、安装来源差异 | 开发第一阶段先验证检测、覆盖层、退出和恢复 |
| 土豆地雷素材能否开源 | 非商业、开源不等于所有素材可以重新授权 | 记录素材来源及权利依据；未明确前使用可分发占位素材，不宣称指定角色已交付 |
| 公开分发是不是永久零费用 | 本地运行无 API/服务器费用，但分发条件可能变化 | GitHub 提供安装包；发布时核查适用地区安装和登记要求 |
| 毒舌能否提高学习效率 | 是待验证假设 | 用户可调语气、屏蔽句子；不声称疗效或学习提升 |

这些问题不要求暂停设计或先搭建商业基础设施，但必须如实写入实现与发布说明。

## 3. 功能范围与优先级

### P0：首个可使用版本必须完成

1. 用户选择已安装的可启动娱乐应用。
2. 设置目标、本次任务、可选个人寄语。
3. 手动开启一个有明确结束时间的学习时段。
4. 每次确认进入目标应用显示角色劝阻；有剩余额度时只允许继续余额，不能重新领五分钟。
5. 三类按钮：回去学习、搜学习资料、休息一下。
6. 按目标应用实际可确认的前台使用时间计时；切应用、锁屏、弹窗占据交互时不继续计娱乐时间。
7. 本地对话记忆、分情境随机台词、占位符替换、避免连续重复。
8. 所有选定娱乐应用共用同一轮放行额度。
9. 默认约定限制模式：最后一段额度结束且不能再放行时自动尝试返回桌面，进入冷却；提醒模式为可选较轻模式。
10. 紧急解除、正常结束时段、权限失效提示、覆盖层清理。
11. 配置与必要会话状态持久化，进程重建不自动赠送额度。
12. 本次记录：可确认的娱乐时长、放行次数、提醒次数、解除情况。
13. 源码、安装包构建方法、隐私说明、素材清单、兼容性与验收报告。

### P1：核心可靠后再做

- 具体目标模板、过去的自己寄语展示增强。
- 自定义台词、屏蔽台词、导入导出语料包。
- 手动开启正式休息：暂停监督，按现实时间到期；不赠送当前轮额度。
- 学习时段内娱乐总上限：独立于“每轮额度”，达到后限制至时段结束。
- 静态个人照片形象、照片删除与可选本地寄语。
- 本地历史与简明复盘；用户自报任务完成。
- 经过实测的品牌权限引导和可选的检测回退方案。

### P2：后续社区拓展

- 动画角色包、角色切换、声音包。
- 定时开启学习时段、有限范围随机提醒。
- 简单专注计时、场景预设。
- iOS 版本的独立可行性验证与原生实现。

首版不做自由 AI 对话、云同步、在线素材商店、好友排行榜、复杂养成、自动识别学习内容、实时语音克隆。P1/P2 不因接口预留而提前全部实现。

## 4. 默认设置及精确定义

以下数字是产品默认值，不是效果研究结果。开始前可修改；活动时段使用冻结的配置快照。没有实际用户验证前，不把这些参数称为最优学习策略。

| 设置 | 默认值 | 含义 |
|---|---|---|
| 学习时段 | 60 分钟 | 按现实经过时间结束，锁屏和监测中断均不延长 |
| 监督模式 | 约定限制模式 | 开始页明确同意三次后退出；可事先改为只提醒 |
| 进入提醒 | 每次确认进入 | 非目标到目标、目标 A 到目标 B、锁屏后回到目标均提醒；页面跳转及临时系统窗口恢复不算新进入 |
| 一次放行 | 5 分钟 | 累计可确认的目标应用前台使用；已切走、锁屏、弹窗显示和 UNKNOWN 时暂停 |
| 每轮最多放行 | 3 次 | 首次加两次续时；理由共用计数；第三次正常给出最后一段，禁止的是第四次 |
| 每轮可发放总量 | 15 分钟 | 所有目标应用共享；按实际发放量预留，主动放弃部分不退回 |
| 冷却期 | 20 分钟 | 按现实经过时间；重入不重新计算 |
| 冷却后 | 新一轮 | 若会话未结束，重置轮内额度和次数；时段累计记录不清零 |
| 语气 | 吐槽 | 温和、吐槽、毒舌三档均可明确选择 |
| 声音 | 关闭 | 首版文字与轻量动画；震动可选 |
| 紧急解除等待 | 10 秒 | 正常工作时确认结束监督的短暂等待；故障退出、撤权和普通结束不等待 |

五分钟不是从按钮点击后计算的无条件闹钟。例如使用两分钟后去学习十分钟，再进入目标应用，只剩三分钟；不能再领完整五分钟，也不在学习工具里追问。若剩余不足一分钟，按钮显示秒数；其余剩余时间向上显示秒，不把舍入显示值写回计时。

本轮总量与本时段总上限是两个概念。默认 60 分钟内，在连续使用、忽略操作耗时的理想情况下可放行两轮，共 30 分钟。该规则用于打断连续分心，不保证这一小时只能使用 15 分钟。开始页写清“每轮，冷却结束重新开始”；时段总上限仍为 P1。

额度统一定义：

- `roundGrantedMs`：本轮已经发放的总量，领取时增加；已发放部分不重新领取。
- `allowanceRemainingMs`：当前已经领取但尚未使用／放弃的余额。
- `confirmedUsageMs`：实际可确认的前台使用时长，供复盘显示。
- `forfeitedMs`：用户明确放弃的当前余额；不计为实际使用，不退回可发放总量。
- `grantCount`：成功领取次数；继续已有余额及普通重入提醒不增加。

下一段发放量为 `min(一次放行时长, 每轮总量 - roundGrantedMs)`。领取次数未满且量为正才可发放。达到次数上限或总量已全部发放，不取消正在生效的最后一段；当前段用完或主动放弃，才进入冷却。

每段的时间关系为：发放时长 = 段内已确认使用 + 剩余 + 主动放弃。调度迟到造成的额外确认使用单独记入超时使用，不从下一轮扣除，不声称精确零超时。

## 5. 核心用户流程

### 5.1 首次设置

1. 简短介绍：监督选定应用、支持毒舌、离线运行。
2. 创建目标：考研／考公／自定义，填写本次任务，可选写给未来自己的话。
3. 选择娱乐应用，默认不替用户勾选应用。
4. 设置提醒强度与限制规则；规则以直白文字呈现。
5. 独立解释无障碍权限用途，用户明确同意后进入系统设置授权。
6. 权限就绪后开始监督，首次进入已选应用时验证提醒。v0.3.1 移除不扣额度的测试模式；设置中的音效试听保留。
7. 首页显示已选应用、权限状态与“开始学习”。

### 5.2 开始学习

开始确认页显示目标、任务、时段结束时间、每轮额度、放行次数、冷却时长、监督模式。用户点“开始”后创建唯一 sessionId，保存规则快照。

角色素材预览可以在未授权时使用，但首页必须显示“仅预览，尚未监督”。不能用角色动画暗示后台检测已经工作。

### 5.3 进入、接受理由与重新进入

首次确认进入目标应用，覆盖层显示角色、当前任务、情境台词和三个主按钮：

- **回去学习**：尝试返回桌面，不扣一次放行；不得声称用户已经开始学习。
- **我来搜学习资料**：接受理由并记录；保存成功后发放一段使用额度，再收起覆盖层。
- **休息五分钟**：与搜资料同样计数及额度，按钮显示本次实际可发放时长。

角色接受理由后可显示一句简短回应，例如“行，五分钟后我回来问你”。不强制延长阅读时间，也不读取用户搜索内容。

已经领取一段，切到其他应用或锁屏只暂停并保留余额。重新进入任一目标应用仍出现劝阻，提供“回去学习”和“继续上次剩余 X 分钟”；不再提供领取完整新一段的按钮，不重新计算使用间隔。继续余额不增加次数，保留原理由。

在这个重新进入的提醒中选择“回去学习”，意味着明确放弃当前余额；按钮旁说明“放弃本次剩余时间”。作废余额立即保存。普通切走、按 Home、临时系统窗口和锁屏不视为主动放弃。首版无需全天悬浮一个中途放弃按钮。

每次真实进入创建一个入口事件 id。同一应用内部跳转、重复事件、旋转及覆盖层自己的事件不创建新入口；同一入口只创建一个提醒。A 到 B 的切换也共用已领余额和轮内次数。

### 5.4 五分钟追问与最后一次放行

一段可确认使用时间用完，且目标应用仍可确认在前台，显示追问；已离开则不跨应用弹窗，下次进入时处理。

默认限制模式的正常链路：

| 时点 | 行为 |
|---|---|
| 刚进入 | 劝阻，允许选择回任务或首次领取五分钟 |
| 第一段用完 | 引用上次理由追问，可领取第二段或回任务 |
| 第二段用完 | 再追问；领取前说明“本轮最后一次，用完将退出并冷却” |
| 第三段用完 | 保存冷却状态，自动尝试返回桌面，不再给第四次 |
| 冷却内重入 | 显示冷却说明并针对这次进入尝试返回桌面 |
| 冷却到期 | 会话仍有效则开始新一轮，下次进入再次劝阻 |

配置使总量或次数较早耗尽时，同样先让当前已发放段正常结束，再限制。若用户在重入提醒中明确放弃最后一段，则在放弃时进入冷却，不等待被作废的余额。触发原因分别显示“本轮放行次数用完”“本轮额度用完”或两者都达到，不把放弃时间显示为使用时间。

冷却截止固定，不因重入、刷新、锁屏或重试系统动作重算。自动返回桌面每次真实进入最多尝试一次；内部事件不能无限触发返回动作。返回成功并确认离开后清理覆盖层；失败时保留可操作的限制说明、手动返回按钮及结束入口，不宣称应用已关闭。

### 5.5 可选提醒模式

前三次仍按同一额度规则追问，但不会自动返回桌面或进入冷却。约定额度结束后，显示“本轮约定已用完”及“回去学习”“知道了，继续使用”。后者开启一个五分钟前台使用提醒间隔，不再增加 `grantCount`；后续提醒另计次数，不伪装成第四次约定放行。

间隔内切出暂停，重入先劝阻；继续当前间隔不重置计时。间隔用完再提醒。选择“回去学习”作废当前间隔，下一次进入先劝阻；选择继续时开启新间隔。本轮超额标记保持到会话结束，提醒模式不因反复进入重置前三次额度，也不自行变成限制模式。

### 5.6 结束、故障退出与复盘

现实学习时段到期、用户主动结束、紧急解除均结束本次监督，清理覆盖层、停止计时与后续返回动作。限制期间仍可访问本应用、设置、拨号与学习工具；主页普通结束立即生效，紧急等待不代表不可绕过。

复盘显示已确认的目标应用使用、作废额度、放行与提醒次数、自动返回动作结果、监测中断及结束原因。冷却时间、未使用目标应用的时间不能标为学习时间。任务完成情况由用户自报，增强复盘为 P1。

## 6. 计时、观察与异常恢复

### 6.1 时间基础与处理顺序

同一次开机使用 `SystemClock.elapsedRealtime()`，包含睡眠时间。学习时段和冷却使用单调截止；日历结束时间只作展示，不因用户调整系统时间改变当前截止。娱乐计时只累计已确认的目标应用可交互区间，不把屏幕亮着等同于实际使用。

每次规则评估先识别结束或权限故障；有效使用结算最多截到会话截止，再决定额度／冷却，最后处理仍有效的按钮。会话结束优先于续时、冷却到期和提醒。一个迟到回调只能依据实际时间差结算，不能按回调次数加秒，也不能自动推演多轮使用和发放。

若一次有效目标区间越过当前段截止，先定位额度实际耗尽的单调时刻；冷却从该时刻起算。已确认的额外前台使用记入超时使用，额度最低为零。第一次发现超时仍执行一次退出，即使迟到已超过冷却截止，也不借此自动补发额度或重建历史中的多轮。随后在下一次评估按现时处理冷却到期。

用户进入其他应用以后不自动 Home、不弹追问；计时暂停的时间不耗用娱乐额度。覆盖层确认显示之后暂停使用计时；创建失败不能假设用户已被挡住。未知区间不猜测使用，以缺口单独报告。

### 6.2 场景行为

| 情境 | 行为 |
|---|---|
| 目标 A 切到目标 B | 劝阻后可继续同一余额；不赠送次数或时间 |
| 切到未选应用或桌面 | 暂停计时并保留余额，清理覆盖层 |
| 锁屏／熄屏 | 暂停使用，清理覆盖层；学习时段及冷却继续经过 |
| 解锁回到目标应用 | 确认后劝阻，余额与次数保持 |
| 通知栏、键盘、权限窗口 | 不当成新入口；不足以确认交互状态时 UNKNOWN 暂停，不覆盖敏感系统页面 |
| 系统临时窗口关闭 | 必须用有效目标事件重新确认；不能只靠旧包名恢复计时，也不创建额外放行 |
| 重复事件／旋转／内部页面 | 合并去重；不重复扣次、不重抽台词、不重置计时 |
| 同时按多个按钮 | sessionId、roundId、promptId 串行处理，只允许一个有效结果 |
| 已开始但无法确认当前前台 | 观察从 UNKNOWN 开始；首页提示切出再进入，不读取正文补救 |
| 分屏、画中画、应用分身、工作资料 | 首版只声明实测支持范围，不误拦其他资料和应用 |
| 权限撤销或服务断开 | 停止计时和覆盖层，标记中断；不得继续显示正常限制 |
| 覆盖层创建／更新失败 | 标记限制失效并中断监督，清理残留；允许立即结束或重新检测 |
| 返回桌面失败 | 记录失败，保留手动退出和结束入口；不无限自动重试 |

UNKNOWN 恢复必须有有效观察证据。无法重新确认时，继续暂停并记录缺口；首页显示“暂时无法确认，计时暂停，请切出目标应用后重新进入”，不能显示“正常监督”。不在不确定的其他应用上叠加提醒。该恢复路径是否在日常通知栏／键盘场景足够可靠是阶段 A 必测项；不通过时记录失败并验证可选回退。

### 6.3 持久化误差与恢复选择

放行、明确放弃、进入冷却和结束立即保存；有效使用尝试每五秒以及离开／锁屏时保存。五秒是计划间隔，不是系统故障下保证的误差上限。

同次开机进程重建：加载最后成功保存的次数、余额和截止，标记 INTERRUPTED；用户确认后恢复，观察从 UNKNOWN 开始。停止期间不计算娱乐时长；已保存的放行不重新发放，未保存的增量可能丢失并披露。不以惩罚性扣时猜测丢失区间。会话或冷却经过时间继续按原单调截止判断。

跨手机重启：首版结束旧会话并标记“重启导致监测中断”，保留已保存记录和设置，用户可重新开始。保存开机标识；无法可靠判定是否同次开机时按重启处理。v1.1 采用此简单恢复规则，取消跨重启恢复旧会话，以免混用失效的单调锚点和可被修改的系统时间。

配置或记录损坏、关键保存失败：不虚假发放、不继续声称正在限制，清理覆盖层并进入故障中断。允许立即结束、重试存储或重建配置；无可读取数据不伪造完整复盘。结束保存失败也立即停止内存监督，并记录／重试持久化；下次启动不自动恢复任何活动会话。

正常结束和故障退出无需十秒等待。只有正常工作时从拦截页选择紧急解除才显示十秒确认；等待按单调时钟，不因重绘重置，取消不结束；期间会话到期或故障仍立即清理。

## 7. 规则状态机

- 会话：OFF／ACTIVE／INTERRUPTED／ENDED。
- 规则：GATE／ALLOWANCE／COOLDOWN／REMINDER（后者只用于可选提醒模式）。
- 观察：TARGET／OTHER／LOCKED／UNKNOWN。
- 提醒是规则输出，带 promptId、入口事件 id、场景与关联的额度 id；“提醒正在显示”是计时暂停条件，不改变已领取额度的事实。

| 状态及事件 | 转换和输出 |
|---|---|
| OFF／ENDED，开始且配置权限有效 | 新 sessionId、roundId；ACTIVE + GATE，观察 UNKNOWN |
| GATE，确认进入 TARGET | 入口劝阻；可领取时显示理由按钮 |
| GATE，有效领取且保存成功 | ALLOWANCE；扣一次，增加发放总量，记录理由；移除提醒 |
| ALLOWANCE，普通离开／锁屏 | 规则不变，计时暂停，余额保留 |
| ALLOWANCE，真实重入任一目标 | 新入口劝阻；只有回任务／继续余额，不提供新的五分钟 |
| ALLOWANCE，继续余额 | 状态不变；消费当前 prompt，不加次数、不重置余额 |
| ALLOWANCE，重入提醒中回任务 | 余额记作放弃；可继续发放则 GATE，否则按模式处理；尝试 Home |
| ALLOWANCE，段结束且还能放行 | GATE；目标仍在前台则追问，否则等下次进入 |
| ALLOWANCE／GATE，无当前余额且不能放行，限制模式 | COOLDOWN；保存固定截止；TARGET 时为当前入口执行一次 Home |
| 同上，提醒模式 | REMINDER，显示回任务／知道了继续；不执行自动 Home |
| REMINDER，继续使用 | 开始五分钟前台提醒间隔；不增加约定放行次数 |
| REMINDER，间隔结束 | 显示超额追问；选择继续才开启下一间隔 |
| REMINDER，离开／重入 | 暂停／劝阻；已有间隔可继续，不能重置为完整五分钟 |
| REMINDER，回任务 | 作废当前间隔，状态仍 REMINDER；下一次进入先劝阻 |
| COOLDOWN，真实进入 TARGET | 限制说明及本次入口的一次 Home；不重算截止 |
| COOLDOWN，到期且会话有效 | 仅新建一个 roundId + GATE；不补算缺失轮次、不立即免费放行 |
| ACTIVE，服务／覆盖层／存储故障 | INTERRUPTED；停止计时和动作，统一清理 |
| INTERRUPTED，同次开机、用户确认且能力就绪 | 恢复已保存规则和原截止；UNKNOWN，过期会话直接结束 |
| 检测到重启／无法判定开机身份 | ENDED，保留记录并标注中断；不恢复旧监督 |
| 任意，会话到期／主动结束／完成解除 | ENDED，结束优先；清理全部窗口、计时和待执行动作 |

当前段剩余大于零时，次数上限与发放总量上限都不能触发提前冷却。提醒暂停不影响已有规则状态。有效按钮必须在执行时再次核验会话、入口、prompt、额度 id 和截止；旧弹窗不能修改新一轮。

配置验证：时段、放行、次数、总量与冷却均为有限正数，空目标列表不能启动；实现时锁定并公布输入上限，用宽整型毫秒避免溢出。配置间不要求总量必须等于单次时长乘次数，实际取较早约束；开始页展示有效上限。

## 8. 语料与角色互动设计

### 8.1 情境与语气

情境键：entry、reentry、accept_study、accept_rest、followup_study、followup_rest、repeat_extension、last_grant、cooldown、over_limit、return_to_task、past_self。

每条语料带稳定 id、情境、语气、模板和可选表情。首版目标至少 45 条，覆盖三档语气与主要追问情境；只是内容覆盖要求，不是每个组合机械凑相同数量。

变量：{goal}、{task}、{grantDuration}、{remainingDuration}、{usedMinutes}、{grantCount}、{extensionCount}、{cooldownMinutes}。grantDuration／remainingDuration 是准确格式化的分秒字符串，避免不足一分钟被写成完整五分钟。次数使用明确口径：grantCount 包含首次放行，extensionCount 是之后续时次数。usedMinutes 仅来自已确认的实际使用，不含作废或未知时间。

角色每次先指出可证明的约定与行为，再给回任务入口。例如“刚才说来找资料，这一段时间用完了。回去把你写下的任务接着做？”不能说“我看见你根本没学习”。学习目标与任务是用户提供的文字，不应被拼成系统控制指令。

规则：

- 先按情境和语气筛选，再随机；本次最近几条尽量不重复，候选不足时有稳定回退。
- 固定当前 promptId 对应台词，重绘、旋转、恢复不反复换句子。
- 模板缺字段时使用通用句，不能向用户显示原始占位符。
- 首版没有无限自由文本回应；按钮选择映射到确定事件。
- 毒舌可以讽刺行为、额度和竞争情境；不虚构观察结论。
- “你就刷吧，把位置让给我”可以作为用户选定毒舌语气的候选，不宣称它一定提高成绩。
- 首版毒舌可讽刺分心行为、讨价还价和竞争情境，保留“你就刷吧，把位置让给我”等风格；不默认收录“反正你也考不上”等否定个人能力的句子。三档语气都保留回到任务的引导，不增加第四个隐藏强毒舌档。保留关闭毒舌与后续屏蔽句子的能力。
- 个人寄语明确标记“你之前写下的话”，不冒充真人发言。

### 8.2 示例语料格式

```json
{
  "schemaVersion": 1,
  "lines": [
    {
      "id": "entry_snark_001",
      "scene": "entry",
      "tone": "snark",
      "expression": "idle",
      "text": "你准备{goal}的计划里，还有刷视频这一项？"
    },
    {
      "id": "study_followup_roast_001",
      "scene": "followup_study",
      "tone": "roast",
      "expression": "suspicious",
      "text": "刚才说来搜资料，{grantDuration}的使用时间用完了，资料找到没？"
    }
  ]
}
```

### 8.3 表现与可访问性

首版三到四个表情足够：待机、怀疑、冷却值班、鼓励。动画不全天悬浮，只在提醒页短暂播放；音效默认关闭，不读取视频音频。支持大字体、横屏和减少动画，按钮面积与文字对比需在实机查看。

动画失败时退回静态图，静态图失败时仍显示文字与操作。视觉资源不得影响限制规则运行。

## 9. 页面与界面要求

### 首页

- 当前目标、本次任务。
- 当前状态：未开启／正常监督／监测中断／仅预览。
- 已选应用数量、当前段剩余、之后还能领取几次、冷却倒计时及学习时段剩余。已领取与未领取余额分开显示；第三次使用中显示“最后一段，还有 X”，不能显示零次后误以为立刻失效。
- 开始／结束、修改设置、测试提醒。

避免将“服务已连接”当作“所有设备情境都可靠监测”。没有端到端证据时不显示实时可靠性百分比。

### 配置页

目标、任务、寄语；目标应用；监督模式；时间和次数；语气、声音、震动。把规则说明放在设置附近，不堆隐藏高级选项。

### 入口与追问覆盖层

上部为角色，中部为台词和具体任务，下部为当前段／次数摘要及回应按钮。初入、续时、已有余额重入、提醒模式超额分别使用第 5 节的按钮。覆盖目标应用的主要交互区域，不让点击穿透；系统返回桌面、设置和紧急操作保持可达。角色不冒充真人，不要求用户输入借口；按钮选择足以表达理由。

### 冷却覆盖层

醒目剩余时间、触发原因、返回桌面、紧急解除及可到达的本应用结束入口。不提供“再休息一下”。每次确认进入时自动尝试 Home，离开后移除覆盖层；动作失败时保留手动退出说明。冷却不是全天遮挡手机，学习工具及必要系统功能继续可用。

### 权限与帮助页

说明读取哪些事件、为什么需要权限、如何关闭。对侧载安装可能遇到的受限设置提供官方说明链接，不伪装成系统页面，也不承诺所有品牌都有相同菜单。

### 本次复盘

只显示已记录事实；监测中断明显标注。实际使用、主动放弃和超时使用分别说明。“提醒后离开”不叫“成功学习”，“未使用选定应用”不叫“专注时长”。目标是帮助回到任务，不用不可证明的“今天多学习了 X 分钟”制造成效。

## 10. 安卓技术路线与第一阶段验证

### 10.1 技术选型

- Kotlin 原生安卓，首版单 app 模块。
- 主页面采用 Jetpack Compose；覆盖层可采用简单原生 View，减少额外生命周期复杂性。
- minSdk 建议 26；compileSdk、targetSdk 采用开发时核实的稳定版本，并在构建文档锁定版本。不能通过降低 targetSdk 绕开系统限制。
- 协程与 AndroidX DataStore 保存设置、规则快照与少量当前会话数据；语料为本地 JSON，优先平台 JSON 工具。
- 规则引擎为不依赖 Android 的 Kotlin 逻辑，便于用可控时钟测试。
- 初期不引入 Room、Hilt、多模块、跨平台框架、插件执行引擎或自建后端。

### 10.2 首选检测与覆盖路线

首选验证 AccessibilityService 的必要窗口状态事件与包名，结合屏幕／锁屏状态，建立有限的前台观察。只使用必要事件元数据，不访问事件文本、节点树、截图、输入内容；先保持 canRetrieveWindowContent=false。

不能在此能力声明下假设 getWindows() 可用，也不默认订阅 TYPE_WINDOWS_CHANGED 就能获得完整交互窗口状态；官方窗口查询及相应标志有能力要求。阶段 A 应明确列出实际事件类型、可区分的应用切换与系统窗口、丢失事件及 UNKNOWN 的恢复证据。无事件本身不证明应用仍在前台或已离开。[窗口查询能力要求](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#getWindows())、[交互窗口标志](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#FLAG_RETRIEVE_INTERACTIVE_WINDOWS)

覆盖层首选 TYPE_ACCESSIBILITY_OVERLAY，由已启用的无障碍服务显示；返回学习优先尝试 GLOBAL_ACTION_HOME。该组合的具体可用性、覆盖层对窗口事件的影响、横竖屏和手势退出必须通过原型验证，不能仅因为 API 存在就宣称通过。

无障碍覆盖层与一般 SYSTEM_ALERT_WINDOW 路线不同。首版不要无条件同时申请无障碍、使用情况访问、悬浮窗、设备管理员等一整套权限。所选路线不需要的权限不声明。

只过滤目标应用事件会漏掉“离开目标应用”，所以服务可以接收必要窗口事件，在内存中判断目标与非目标；非目标应用身份不写入历史。过滤与去重不能将输入法、系统界面、本应用覆盖层误判为新的娱乐进入。

窗口事件不能当作完美的当前前台真相。P0 必须验证启动、返回、通知栏、键盘、旋转、锁屏、覆盖层显示和事件缺失；无法确认时进入 UNKNOWN，暂停累计，避免错拦。

本应用自己的覆盖层事件不能被误判为用户离开目标应用，也不能反过来被当作目标应用持续使用的证明。维护覆盖层显示前的有效观察，弹窗期间暂停娱乐计时；关闭自有覆盖层后只有有效目标观察仍成立且无外部未知窗口介入才恢复，否则 UNKNOWN。检测到明确外部切换时清理。临时系统窗口恢复不触发新的重入提醒，避免自行弹出／自行移除循环。

Home 副作用在保存规则成功后执行，携带 sessionId、roundId、入口事件 id；执行前再次判断仍是有效会话和目标应用。动作返回值及后续离开证据分开记录。“动作请求成功”不当作已经完成学习。onInterrupt 是反馈中断回调，不单独当作权限已撤销证据；结合服务生命周期、权限检查和窗口故障处理实际失效。

### 10.3 回退与后台执行

若最小权限事件路线在目标设备不足，先记录复现，再决定是否以 UsageStats 查询作为可选回退。不得通过偷偷打开界面读取能力补救，也不要首版同时维护两套各自计时的监督器。

服务连接期间由单一规则引擎调度计时；屏幕关闭停止高频调度。初期不另建用于“保活”的前台服务。若实测确实需要前台服务，核查适用类型、启动条件和通知，说明理由后再引入；不能把任意长期任务冒充其他服务类型。

Android 14 起前台服务有类型与权限要求；specialUse 也需要声明具体用途，未来 Google Play 发布涉及用途审查。[前台服务官方文档](https://developer.android.com/develop/background-work/services/fgs/service-types)

后台被停止时没有绝对保活承诺。不要误导用户关闭全局安全措施，不修改其他应用、系统代理或与项目无关的设置。

### 10.4 应用列表与权限

应用选择展示可启动应用，使用包可见性声明满足所需查询，先不申请 QUERY_ALL_PACKAGES；隐藏本应用及系统关键工具，不能默认禁止系统设置、桌面、拨号、权限页面。[包可见性官方文档](https://developer.android.com/training/package-visibility/declaring)

应用分身／不同用户资料不能简单当同一包名已完全支持；写入兼容性矩阵。

无障碍服务说明明确：用于判断选定应用进入与离开、显示提醒、按用户预设规则返回桌面；不读取视频或聊天内容。项目不是专为残障用户设计，不能为减少说明而伪称 isAccessibilityTool=true。未来上架 Google Play，需要披露、同意与相应声明，且不得阻止用户停用或卸载。[Google Play 无障碍政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)、[相关限制政策](https://support.google.com/googleplay/android-developer/answer/18258653?hl=en-GB)

侧载安装在部分系统会涉及受限设置，应提供透明说明，路径按实机验证。[安卓受限设置说明](https://support.google.com/android/answer/12623953?hl=en-en)

## 11. 最小代码组织与数据

建议单模块按职责分包，不先建庞大的架构：

```text
app/
  ui/            首页、配置、权限说明、复盘
  monitor/       无障碍事件、观察状态、屏幕状态
  rules/         规则引擎、时钟、额度和状态转换
  overlay/       覆盖层创建、去重、按钮、清理
  content/       语料筛选、变量替换、角色资源
  storage/       设置与当前会话持久化
  assets/        本地语料和可分发角色资源
docs/            构建、隐私、兼容性、素材说明
```

最小数据对象（时间一律用毫秒，展示再格式化）：

| 对象 | 关键字段 |
|---|---|
| UserSettings | goal、task、pastSelfNote、selectedPackages、tone、mode、时长与次数 |
| Session | id、schemaVersion、状态、配置快照、bootId、单调开始／截止、日历展示时间、实际使用／超时／放弃统计、监测缺口与结束原因 |
| Round | id、轮次、总量、roundGrantedMs、grantCount、理由序列、固定冷却截止与原因、提醒模式超额标记 |
| Allowance | id、关联 roundId、发放时长、段内已用／剩余／放弃时长、理由、状态；提醒模式间隔单独标记不作为约定放行 |
| Prompt | id、entryId、scene、lineId、关联 sessionId／roundId／allowanceId、消费状态、实际显示记录 |

事务边界：一次放行的计数、理由、发放总量、当前段和 prompt 消费在同一个串行操作中更新并持久化；只有保存成功才收起弹窗。放弃余额、开始冷却、结束也按同一边界处理。出现关键保存失败时中断监督并允许立即结束。

提醒次数只在覆盖层确实显示时对 promptId 计一次，不把绘制／倒计时刷新算成提醒。使用一个共享 DataStore 实例持久化完整当前状态，首页和无障碍服务默认同进程；不把一次逻辑事务拆成若干可能只保存一半的独立文件。不另做事件数据库。

立即保存与周期检查点、同开机恢复和跨重启结束统一按第 6.3 节执行。重连不自动开始活动计时；用户确认以前不得显示后台正在监督。不要把无法保存的错误原因假定已经写入磁盘。

首版只保留本次／最近一次会话；历史扩展默认滚动保留 30 天，用户可清空。不要持久化所有非目标应用活动轨迹。

## 12. 后续角色、照片与 MOD 的预留

现在只分离角色资源与规则，不实现通用插件框架。后续角色包可以使用 ZIP：

```text
manifest.json
images/idle.webp
images/suspicious.webp
images/cooldown.webp
images/encourage.webp
dialogue.json
```

manifest 记录 schemaVersion、id、name、author、license、来源、表情映射和可选台词。缺表情回退到静态图，缺台词回退到内置语料。

未来导入只接受声明的图片、帧动画和文本；不执行脚本，不允许修改监督规则，不访问网络。导入时限定压缩包体积、解压后总量、文件数量、图片像素与帧数，拒绝路径穿越和损坏文件。具体限额开发时按渲染与内存测试定，不能仅靠文件后缀检查。

个人照片是独立简易入口，通过系统选择器取图，复制至应用私有目录并缩放；不申请全相册访问，不上传、不自动加入公开角色包。真人形象默认使用用户寄语／温和台词，不自动套用土豆毒舌；任何其他语气由用户自己明确选择。删除照片时同步删除副本。

## 13. 隐私、素材和费用边界

### 隐私

首版不声明 INTERNET 权限，不使用联网统计、远程崩溃收集、自动上传或在线角色库。检查合并后的 Manifest 与依赖，确认没有意外增加权限。普通数据备份明确禁用，避免将用户寄语和会话记录自动带出设备；不同品牌设备迁移行为仍需说明，不承诺所有系统都绝对不复制。

诊断只由用户主动导出，默认包含设备型号、系统版本、权限状态、匿名规则事件与错误，不包含目标全文、个人寄语、照片、视频、聊天或完整应用活动。用户可先预览再分享。

### 素材

代码许可建议 MIT，素材许可分开列入 ASSETS.md。EA 的内容政策允许满足条件的部分个人／粉丝内容使用，也有品牌、作品类型和第三方素材限制；不能据此直接认定本应用或所有素材已获授权。公开分发前核查具体角色图、动画、音乐来源与适用条件。[EA 内容政策](https://help.ea.com/en/articles/security-and-rules/ea-content-policy/)

开发可以先使用明确可分发的占位角色完成机制。正式土豆地雷形象未落实时，要写“机制可运行，指定角色素材待落实”，不能将原创替代或占位图当作已经完成用户指定角色。

### 费用

运行层面不需要大模型或服务器费用。真实成本是开发时间、实机测试、素材制作和分发维护；不写“整个项目永远零成本”。

GitHub Release 可承载安装包和发布说明，但不代表所有地区 Android 安装要求均被绕过。安卓开发者验证正在分地区实施，免费有限分发与公开广泛分发条件不同；发布时核查所在地区和用户范围。官方目前列出免费有限分发最多 20 台设备，完整分发账号费用 25 美元；适用安装条件以发布时官方说明为准。[官方分发与验证说明](https://support.google.com/android-developer-console/answer/16561738?hl=en)

iOS 暂缓，避免首版增加独立开发、发布权限和会员负担。[苹果会员说明](https://developer.apple.com/support/compare-memberships/)

## 14. 开发阶段与交付顺序

### 阶段 A：先证明系统能力

构建最小可安装原型：选择一个测试应用、获取必要授权、检测进入和退出、显示覆盖层、接受理由后计时追问、第三段结束后自动 Home、冷却重入拦截、锁屏及撤权清理。验证通知栏／键盘关闭后的 UNKNOWN 恢复、覆盖层事件不会形成循环。不先做精美角色、MOD 或完整统计。

调试测试允许缩短时间以重现链路，测试报告必须列出真实使用的秒数，正式默认仍为五分钟；不得把缩短测试说成已经完成五分钟实际计时实测。

交付 APK／可复现构建、测试环境、实际权限、设备与系统版本、测试步骤、结果和限制。模拟器只能证明其对应环境；没有真实手机时把实机兼容明确标为未验证。

如果路线不稳定，保存失败步骤、事件类型、平台与日志摘要，先调整或验证回退；该检测路线不能被标记为通过。独立规则测试、本地构建及文档可以继续，完整后台交付等待端到端证据。只有预览或模拟器结果不能替代真实目标应用及手机验证。

### 阶段 B：实现规则与持久化

完成第 4—7 节的状态机、最后一段有效期、发放／使用／放弃分账、共享额度、每次真实重入提醒、固定冷却、提醒模式间隔、会话截止、紧急解除、同开机恢复与跨重启结束、事件去重。使用可控时钟做关键规则测试。

### 阶段 C：实现完整体验

首页、设置、授权引导、内置语料、简单角色表现、追问、寄语、本次复盘。确认语料引用次数和时间与规则一致。

### 阶段 D：首版发布准备

完成真实安装路径、兼容性矩阵、README 演示、隐私说明、素材清单、构建说明、已知问题、版本记录。未经用户明确指示不推送仓库、不发布 Release、不购买账号或服务。

不承诺固定完成天数；阶段 A 的设备验证会影响后续工作量。

## 15. 验收标准

### 规则测试：必须通过

| 测试 | 必须出现的结果 |
|---|---|
| 默认三次五分钟 | 三段都有效；第三次领取不立刻冷却，第三段结束才退出，无第四次 |
| 实际使用两分钟后离开十分钟 | 使用记录为两分钟，余额三分钟；回到目标先劝阻，继续后不重新给五分钟 |
| 目标 A 切 B | 弹出一次重入劝阻，共用余额／次数；内部页面及重复事件不重复弹 |
| 领取五分钟、使用一分钟、重入时明确回任务 | 使用一分钟，作废四分钟，发放总量五分钟；不返还发放量，不多扣一次 |
| 自定义单段五分钟、总量十二分钟、三次 | 依次五／五／二分钟；最后二分钟正常有效，用完限制 |
| 自定义总量二十分钟、最多三次五分钟 | 三段用完后因次数进入冷却；未发放五分钟不继续领取 |
| 覆盖层、未选应用、锁屏和 UNKNOWN | 不错误累计娱乐使用；系统临时窗口恢复不重置额度或新发放 |
| 旧 prompt／重复按钮／并发按钮 | 当前有效操作只生效一次；旧会话／旧额度不能被改变 |
| 提醒模式完成三段 | 不自动 Home、不冷却；继续后每累计五分钟提醒，grantCount 保持三 |
| 提醒模式重入及回任务 | 继续间隔不刷新计时；明确回任务作废间隔，下一次仍先劝阻 |
| 冷却内重入三次 | 截止保持相同，每个真实入口最多一次自动 Home，其他应用可用 |
| 回调晚到三秒 | 定位实际额度截止，确认的额外三秒单独记录；无负余额、无多轮补发 |
| 会话结束与续时／冷却到期同时到达 | 结束优先，无新放行、无后续提醒和 Home |
| 同开机异常恢复 | 原次数／余额／单调截止恢复；未知区间标注，不赠整段、不推测使用 |
| 重启或开机身份不明 | 旧会话结束并标注中断，不跨重启使用旧单调锚点 |
| 保存／覆盖层故障与权限撤销 | 不虚假发放或限制，清理并立即可结束，启动不自动复活旧会话 |
| Home 失败 | 失败可见，手动返回／结束可用，重复内部事件不无限重试 |
| 正常结束／紧急解除／故障退出 | 前两者按各自确认规则结束；故障立即清理，十秒等待不重绘重置 |
| 语料与格式 | 理由／次数正确，分秒与实际发放对应；缺变量有回退，同一 prompt 不重抽 |

规则测试证明确定性逻辑，不能证明无障碍事件在某台设备上的可获得性。

### 实机测试：首版应覆盖，证据缺失就标为待验证

1. 完全离线开启、提醒、追问和冷却。
2. 在至少一个真实娱乐应用上执行完整链路；如只有可控测试应用，明确不能代表抖音或游戏实测。
3. 各做三次进入／退出、目标应用切换、锁屏／解锁、横竖屏测试；检查每次真实重入提醒且余额不刷新。三次是初期验收样本，不代表长期可靠。
4. 键盘、通知栏、权限窗口、本应用设置页不被错误封锁；系统临时窗口关闭后有可复现的恢复证据，不永久静默停留 UNKNOWN。
5. 会话运行中撤销权限，覆盖层与监督状态正确清理。
6. 模拟同次开机进程重建、重启、改变系统时间：分别验证确认恢复、旧会话结束、当前单调截止不变；标出检查点丢失。
7. 最后一段结束自动返回桌面；重新进入冷却应用被拦截并再次尝试 Home，离开后其他工具可用；失败时手动退出可操作。
8. 至少一次正常安装／更新，确认数据与签名更新路径；不只运行开发环境里的演示。
9. 字体放大、动画关闭、旋转时按钮可操作，紧急解除入口可达。
10. 记录 30 分钟启用后的电量、进程、事件量与异常，并与同场景未启用记录比较；控制亮度、网络、目标应用场景和温度，注明粗略电量读数局限。无测量不声称低耗电或提升百分比。

建议阶段 A 的性能目标：普通单前台场景下，事件可获得时，三次进入均在约 2 秒内提醒；退出后约 1 秒内清理。计时规则本身不因回调频率累计漂移。这些是待测目标，不是跨设备保证；不达标先记录分布和原因。

兼容性矩阵逐台填写：设备型号、Android 版本、安装来源、权限路径、目标应用版本、检测、清理、计时、冷却、恢复、结果、证据。未经测试的品牌写未验证，不能填“支持全部安卓”。

### 成效与传播

不把 Star 数、减少娱乐时间、提升学习成绩作为工程通过条件。后续用户试用可观察是否关闭监督、是否减少超过自定计划的使用、是否自报完成任务；只记录本地可证明信息，不替学习效果下结论。

## 17. 工作模式执行边界

按本方案推进真实安卓实现，而不是只写网页、原型图、架构空壳或弹窗预览。先读取工作目录已有文件与 AGENTS.md，保护已有内容，再做环境检查。

进入开发任务后，能够在当前环境完成的构建、规则验证、安装包和文档应完成。若当前用户只要求完善设计，交付修订文档后停止，不自动开始代码实现。设备与系统能力无法验证时，列出缺口与下一步；独立工作可以继续，相关后台与兼容验收保留待验证。
