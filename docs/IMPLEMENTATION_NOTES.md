# v0.1.0 实现决定与设计差异

本项目以 `DESIGN.md` v1.1 为行为约定。本文件记录实际开发中作出的调整；设计文档本身保留原始约定与当时的未验证状态，不能用它判断今天的测试结果。

## 窗口检测的权限调整

首先实现了只监听窗口包名事件、`canRetrieveWindowContent=false` 的路线。实际 Android 16 模拟器测试发现：通知栏关闭后不能可靠重新确认目标前台；旋转可能被误判为真实重入。该试验没有通过，不把失败结果写成“已支持”。

最终路线同时接收 `TYPE_WINDOW_STATE_CHANGED` 与 `TYPE_WINDOWS_CHANGED`，从事件中建立内存窗口编号—包名映射，并查询当下窗口的类型、焦点与活动状态。键盘和具有交互焦点的系统窗口出现时进入 UNKNOWN；关闭后用当前窗口元数据与映射重新确认。没有新确认时继续暂停。内部页面与旋转保持同包名入口连续性；离开、切换目标应用或解锁重入会重新提醒。

安卓为 `getWindows()` 要求声明 `canRetrieveWindowContent=true` 及 `FLAG_RETRIEVE_INTERACTIVE_WINDOWS`，见 [Android 官方接口说明](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#getWindows())。因此系统授予的能力比原先试验更宽。实现不调用窗口根节点、事件源、事件文本、窗口标题、截图或输入读取；这属于代码使用范围约束，不能把更宽的系统授权描述为“系统只能给它包名”。

应用授权弹窗、系统服务说明和 PRIVACY.md 均披露该变化。窗口映射只在内存中使用，进程重建后不恢复旧前台判断。多窗口或未知窗口采取暂停策略；这可能造成少记时间，不承诺分屏、悬浮视频、投屏或折叠屏无缝覆盖。

## 自动退出的实际含义

通过无障碍全局 HOME 动作返回桌面，并在冷却内重新进入选定应用时再次尝试 HOME。不结束第三方进程、不清理后台任务，不能保证停止音频。动作先持久化一次执行标记，再提交系统动作；记录系统返回的成功／失败，不能据成功返回值推导所有手机都已停止娱乐。

## 角色与后续功能

目前为原创静态占位角色与 63 条原创本地台词，没有交付指定游戏的正式角色素材。没有 AI 接口、照片、MOD、家长端或服务器。动画与照片属于后续功能，不伪装为已完成。

P0 提供当前／最近一次记录；长期历史、用户自报任务完成、整场娱乐总上限、独立正式休息和语料导入导出属于 P1，尚未实现。主动诊断文件导出也未实现；当前不自动收集或上传诊断。兼容与实测范围以 TEST_REPORT.md、COMPATIBILITY.md 为准。

## 计时与存储

规则只由一个串行引擎管理。使用 `elapsedRealtime`，娱乐使用按已确认前台累计；系统墙上时间变化不延长截止。放行、提醒与 HOME 状态变化先保存后生效；普通累计每五秒保存一次，异常终止可能损失尚未保存的最后一段。保存失败进入中断，同次开机恢复需要本人确认，重启终止旧会话。未知区间不猜测为娱乐或学习。

## 验收工具与环境

界面测试 APK 是独立可控目标应用，仅供隔离模拟器。测试框架需要显式保留无障碍服务，并在框架强制停止被测进程后重新连接。测试中的权限设置由测试框架完成；产品没有自动启用无障碍的代码。

本次不改 Windows 全局／用户代理与系统环境变量。工具链与缓存位于工作目录，SDK、JDK 不打入源码交付。CI 配置提供相同构建入口，本次不宣称已运行远程 CI 或已发布 GitHub。
